# SwitchPad —— 用安卓手机当 Windows(Switch) 的蓝牙键盘 + 触控板

给装了 Windows 11 ARM 的 Switch / Switch Lite 用的一套**手机端输入外设**：
手机充当标准蓝牙 HID 设备（键盘 + 鼠标 + 音量/媒体键），电脑侧**不需要装任何程序、不需要驱动、不需要 root、不需要数据线**。
Windows 只看到一只普通蓝牙键鼠，所以和你贴的那张驱动适配表里的 GPU / 显示 / GPIO / I²C 等任何一项都无关——
本方案刻意不去碰驱动层。

```text
┌──────────────┐   蓝牙经典 L2CAP(HID)     ┌─────────────────────────┐
│  安卓手机     │  ───────────────────────▶ │ 电脑 = Switch 上的 Win11 │
│ HID Device   │   Report ID 1 键盘(8B)     │ HID Host                │
│ (从设备)     │   Report ID 2 鼠标(4B)     │ 标准键鼠驱动 → SendInput │
│              │   Report ID 3 消费类(2B)   │                         │
└──────────────┘                            └─────────────────────────┘
```

## 为什么是这个方案

对照那张《Switch 全驱动适配总览》：

| 表里的项 | 本方案的取舍 |
| --- | --- |
| 蓝牙（T214 续航版/Lite）：`复用主体；核对启动与唤醒` | 蓝牙栈本身有驱动，能配对、能发现设备；真正不确定的是唤醒/启动时序。所以手机端**只依赖配对后的一条 HID 连接**，不要求它承担任何驱动级职责 |
| 触屏（FT4M）、手柄/震动、传感器 | 一律不动。不写驱动、不注入、不 hook 内核——出货驱动是否齐全与本工具无关 |
| GPU/Vulkan、显示输出、电池/充电、风扇 | 完全无关，本工具纯输入外设 |
| 深度睡眠/恢复 | 电脑睡眠后 HID 连接会断，醒来在手机上重连即可（见「排查」） |

也就是说：**先把「能操作」这件事用标准蓝牙外设解决，再去逐项推进驱动移植。**
这样即使显示/触屏还在调试，也能用手机把 Windows 操作起来、跑安装、做验证。

## 构建与安装

只用本机 JDK 17 + Android SDK（build-tools 34），**不需要 Gradle、不需要联网**：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1      # 产出 SwitchPad.apk
powershell -NoProfile -ExecutionPolicy Bypass -File tools\test.ps1 # 纯逻辑自测
```

安装：`adb install -r SwitchPad.apk`，或把 APK 拷到手机上点开安装（需允许未知来源）。

- minSdk 28（Android 9），targetSdk 34。**Android 9 以下无法使用**：从设备 HID 角色是 API 28 才开放的。
- 包名 `com.switchpad`，图标/名称：SwitchPad 键鼠。

## 首次配对（一次就好）

手机端：

1. 打开 App → 允许「附近的设备」权限（Android 12+ 必须）→ 允许通知。
2. 点「打开蓝牙」（若未开）。
3. 点「**让电脑发现本机**」（120 秒可发现窗口）。

电脑端（Switch 上的 Win11）：

4. 设置 → 蓝牙和其他设备 → 打开蓝牙 → **添加设备** → 蓝牙 → 选择 **SwitchPad** → 配对。
5. 手机上若弹出配对确认，点「配对」。

成功后 App 顶栏显示 `● 已连接 <电脑名>`，配对面板自动消失，屏幕即为触控板 + 键盘。
Windows 的设备列表里会出现「SwitchPad」，归类为键盘/鼠标设备。

**重连**：电脑重启或离开范围后，回 App 直接点「连接 <电脑名>」（已配对设备列表里），
或从电脑侧点一次该设备即可；Windows 通常也会自己重连。

## 手势与按键

触控板（上半屏）：

| 手势 | 动作 |
| --- | --- |
| 单指拖动 | 移动指针（亚像素累加 + 速度加速，慢速可精调） |
| 单指轻点 | 左键单击 |
| 双指轻点 | 右键单击 |
| 三指轻点 | 中键单击 |
| 双指上下滑 | 滚轮（每 46dp 一个棘轮，可在设置里调） |
| 单指长按后拖动 | 拖拽（按住左键移动，松手释放） |

快捷动作条（触控板与键盘之间）：`L` `M` `R`（按住即为按住该键）、
`C+A+Del`（Ctrl+Alt+Del）、`Alt+Tab`、`⊞+D`（显示桌面）、`Esc`、`Vol−/Vol+`、以及最右的模式按钮。

**布局三档**（点动作条最右按钮循环切换，或**长按顶部状态条**也能切；选择会被记住；返回键先回分屏，再返回一次才退到后台）：

| 档位 | 效果 |
| --- | --- |
| `分屏`（默认） | 上半触控板 + 下半键盘 |
| `触控` | 键盘整块隐藏，触控板独占除状态条/动作条以外的全部高度（放大约 2 倍，适合精细定位、长时间移动指针） |
| `键盘` | 触控板整块隐藏，键盘独占全部高度（5 行键位每行约 130dp，键帽明显变大，适合长时间打字） |

三档只改可见性与权重，不重建 View，所以切换是瞬时的；`⚙` 始终留在状态条上，
即使在全屏档位也能立刻调灵敏度（拖动即时生效）。

屏幕键盘（下半屏）：

- 标准 US QWERTY，`⇪` 由电脑侧处理（真 Caps Lock），`⌫`/`⏎`/`⇥`/方向键齐全。
- 修饰键是**锁存式**：点 `Ctrl`/`Alt`/`⊞` 保持按下、再点取消；`⇧` 是**一次性**（打完一个键自动弹起），**双击 ⇧ 锁定**。
- 支持多点：一根手指按住 `⇧`、另一根敲字母也正常。
- 点 `Fn` 把数字行切到 `Esc F1..F12 Del` 页。
- 顶栏右侧会显示电脑回读的 `NUM / CAPS / SCR` LED 状态。

设置（顶栏 ⚙）：指针速度、滚轮灵敏度、指针加速、自然滚动、轻点即左键、长按拖动、触觉反馈。

## 实现要点

**1. 从设备角色**：`BluetoothAdapter.getProfileProxy(..., BluetoothProfile.HID_DEVICE)` 拿 `BluetoothHidDevice`，
再 `registerApp(SdpSettings, ...)`。SDP 子类 `0xC0`（键盘 | 定点设备）。

`registerApp` 在 API 33 换过签名（Handler → Executor），而 android-34 的 stub 里只剩 Executor 版本，
所以 `HidCore.registerAppCompat()` 用反射依次尝试两种重载，Android 9 ~ 15 都能注册上。

**2. 报告格式**（见 `HidDescriptor`）：

- Report ID 1 键盘：`[modifiers, 0, key1..key6]`，输出报告 1 字节（LED）用于回读 Caps/Num。
- Report ID 2 鼠标：`[buttons, dx, dy, wheel]`，dx/dy/wheel 为 int8。
- Report ID 3 消费类：`[usage_lo, usage_hi]`，音量/媒体/亮度。

Android 系统内置的 HID 描述符与上面这三套一致（多数 ROM 会忽略 App 传入的 descriptor、用内置那份），
所以报告 ID 按 1/2/3 发送即可；`HidDescriptor.reportDescriptor()` 保留了完整描述符，
以后要做 BLE-GATT-HID（可自定义 Report Map）时直接复用。

**3. 发送节流**：鼠标位移在 8ms 窗口内合并，超过 ±127 自动拆成多帧余量续发；
按键用「按下 → 16ms → 抬起」保证主机能看到完整行程；`setModifier` 状态未变时不发报告。

**4. 指针数学**（`PointerModel`）：`residue += dx * gain`，取**整数部分**（向零截断）发送，
零头留给下一次；增益 = 灵敏度 × (1 + min(speed/3000, 1.0))，即慢速 1.0x、快速最多 2.0x。

默认灵敏度 **0.45**，量级验算（1080 宽屏幕、整屏滑动 ≈ 1080 物理像素）：

| 灵敏度 | 慢速滑动一次 | 快速滑动一次 |
| --- | --- | --- |
| 0.30x | 324 counts | 648 counts |
| **0.45x（默认）** | **486 counts** | **972 counts** |
| 1.00x | 1080 counts | 2160 counts |
| 1.70x（早期默认，太快） | 1836 counts | 3672 counts |

1920 宽的桌面通常希望 2~3 次整屏滑动走完（即每次 600~900 counts），所以默认落在 0.45x。
可在设置里 0.10x~3.00x、步进 0.05x 调整，**拖动即时生效**，不用重连。

**5. 断连安全**：连接断开或切换主机时 `releaseAll()` + 清掉锁存修饰键，避免电脑侧按键卡住。

## 排查

| 现象 | 处理 |
| --- | --- |
| 电脑搜不到 SwitchPad | 1) 手机点过「让电脑发现本机」吗？窗口只有 120 秒；2) 手机蓝牙已开且未被别的 HID 应用占用；3) 电脑蓝牙本身是否可用（设备管理器看蓝牙适配器有没有黄色感叹号） |
| 手机提示「注册 HID 应用失败」 | 面板上会展开**诊断块**（适配器/代理/注册/尝试次数/系统回调/HID 通道状态），并给出三个按钮：「重试注册」「重置 HID」「蓝牙设置」。常见成因与对策见下面的《注册失败处理》 |
| 电脑显示已配对，但按键/鼠标没反应 | 先断开重连一次；再看顶栏是否 `● 已连接`。若电脑端把设备识别成「其他设备」而非键盘/鼠标，多半是 Report ID 与系统内置描述符不匹配，见下条 |
| 音量/媒体键无效 | 个别 ROM 的消费类报告 ID 不是 3；键盘和鼠标不受影响 |
| 光标跳动/过慢 | 设置里调「指针速度」，关掉「指针加速」对比；屏幕刷新率高的手机建议速度调低 |
| 电脑睡眠后失效 | 电脑唤醒后回 App 点一次「连接 <电脑名>」 |
| 息屏后失效 | 本 App 有前台服务常驻，正常不应失效；若被系统杀掉，检查「电池优化 → 不优化 SwitchPad」 |
| 想彻底不用手机界面 | 做不到——这就是输入设备本身。但可把手机一直放在支架上，屏幕常亮已开启 |

**关于驱动侧**：如果这台 Switch 的 Windows 蓝牙栈本身不工作（适配表里蓝牙那行写的是
「复用主体；核对启动与唤醒」，说明它是被复用而不是重新编写、且启动/唤醒时序仍待验证），
那问题不在手机端。此时有两条替代路线，都不用改手机 App 的输入层：

1. **BLE-GATT-HID**：把 `HidDescriptor` 里的描述符塞进自建 GATT 服务（HID Service 0x1812），
   走 BLE 而不是经典蓝牙，适合只有 LE 可用的机器。
2. **Wi-Fi + 电脑侧注入**：手机发 TCP/UDP 事件包，电脑跑一个几十行的 `SendInput` 接收端
   （PowerShell + `Add-Type` 就能做），完全不依赖蓝牙栈。代价是电脑侧要装东西。

## 注册失败处理（实测踩过）

`registerApp()` 返回 false 基本只有三种原因，按概率排：

1. **蓝牙栈里留着上一次注册的 stale 记录**。上一个占用 HID Device 角色的 App 被强杀/崩溃时，
   注册状态不会被自动清掉，于是下一次注册直接被拒。**解**：关一次手机蓝牙再开（或「重置 HID」按钮），
   顽固情况需要重启手机。
2. **另一个 App / 设备正占着这个角色**。同时只允许一个 HID Device 注册。**解**：断开并"忘记"那个
   把手机当 HID 主机的设备（例如以键鼠快门形式配对的手环/自拍器），强停同类 App。
3. **蓝牙刚打开、HID 接口还没 ready**。**解**：等 1~2 秒重试。

App 已内置：注册失败自动重试 3 次（间隔 1 秒）、`onAppStatusChanged=false` 时退避重试、
诊断面板、「重试注册」/「重置 HID」/「蓝牙设置」三个按钮。

实测有效的一条路径：**手环断开 + 重开 App** → 注册成功 → 电脑侧此前配对记录仍在 →
下次直接在「已配对设备」里点一下电脑名即重连成功，打字与触控板即刻可用。

## 蓝牙版本与兼容性（3.0 / 4.x / 5.x）

结论先说：**本 App 走的是经典 BR/EDR 的 HID Device Profile，天然向下兼容 BT 3.0，全程不碰 BLE。**

判断兼容性时，"蓝牙 3.0 / 5.0"这个版本号本身并不参与协商，真正决定能不能用的是**传输层 + Profile**：

| 路线 | 用到的传输 | 需要主机支持 | 在老/残缺栈上的表现 |
| --- | --- | --- | --- |
| **本项目：HID Device（经典）** | BR/EDR，L2CAP PSM 0x11 控制 / 0x13 中断，配 SDP 记录 | 任何支持 "Bluetooth HID" 主机的栈（Windows 从 Win7 起内置） | 稳妥，BT 2.1/3.0 级链路即可 |
| BLE-GATT-HID（HOGP） | LE，GATT 服务 0x1812 | 主机要支持 HID over GATT | 驱动不全/只做经典栈的机器上容易卡死或完全无反应 |

所以"只支持 BT 3.0 就卡死、非得 5.0"这类现象基本都出在 **BLE 那条路**上；
本项目代码里**没有任何** `BluetoothGattServer` / `BluetoothLeAdvertiser` / `BluetoothLeScanner` /
`startAdvertising` 调用（可自行 grep 验证），`registerApp()` 交出去的就是经典 HID 的 SDP 记录。
清单里的 `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT` 只是 Android 12+ 访问蓝牙的权限门槛，不代表用了 LE。

### 实测背景：那台 Switch 只认「3.0 模式」外设

手头的蓝牙鼠标/键盘都要**拨到 3.0 模式**才能连上那台 Switch（Win11 ARM，蓝牙驱动来自 Switch 的 Ubuntu/Linux 侧移植），
BLE 模式则完全不行。这说明：

- 主机侧的 **经典 HID Host** 是通的（否则 3.0 模式的键鼠也连不上）；
- 主机侧**不接受 LE / HOGP**；
- 本项目是经典 HID **Device** 侧，与那些键鼠走**同一条** BR/EDR 链路，只是角色相反 ⇒ 不需要任何"模式切换"。

也就是说：能不能连上，取决于经典链路 + HID Profile，跟"手机是蓝牙 5.0 芯片"无关。

### 反向配对（从手机扫描电脑）

主机的蓝牙栈是移植来的，若**电脑侧发起配对没反应**，可反过来由手机发起：

1. Switch：设置 → 蓝牙和其他设备 → **更多蓝牙选项** → 勾选「**允许蓝牙设备查找此电脑**」
2. 手机 App 面板 → 点「**从手机扫描电脑**」→ 列表里出现电脑名（带信号强度）
3. 点该条目 → 手机发起绑定 → 弹出确认点允许 → `BOND_BONDED` 后 App 自动 `connect()` 建 HID 连接
4. 顶栏出现 `● 已连接 <电脑名> · 经典 BR/EDR` 即成功

实现位于 `HidCore` 的 `startDiscovery()/bond()` 与 `btReceiver`
（监听 `ACTION_FOUND` / `ACTION_DISCOVERY_*` / `ACTION_BOND_STATE_CHANGED`，绑好即连）。

怎么现场确认：

1. 连上后 App 顶栏显示 `● 已连接 <主机名> · 链路类型`；注册异常时展开的诊断块里也有一行 `链路类型：`。
   本方案只可能显示 **经典 BR/EDR** 或 **双模**（对端同时支持经典与 LE，但实际用的仍是经典 HID 通道）。
   如果显示 `LE`，说明对端是用 LE 连的——本项目不会走到那条路。
2. Switch 侧：设备管理器 → 蓝牙 → 适配器属性 → 详细信息里能看到 LMP 版本；同时"蓝牙"下应出现
   HID 键盘/鼠标设备节点（`kbdhid` / `mouhid` 挂在 HID 主机枚举器下）。
3. 若在 Switch 上配对直接卡死，多半是 WoA 蓝牙驱动在**启动/唤醒时序**（正是适配表那一行的备注）
   或链路类型上报上有问题，而不是本 App 走了 5.0。先关一次蓝牙再配对；仍不行就回到驱动侧确认。

## 现象：能配对成功，但「连接一会儿就断开」

这是**配对成功、HID 建链失败**，不是配对失败。已定位到三个成因，前两个已在代码里修掉：

| 成因 | 机理 | 处理 |
| --- | --- | --- |
| **配对顺序错了** | App 没注册时配上的对：电脑 SDP 里查不到 HID 服务，就缓存成「已配对但无输入设备」，之后每次去建 HID 链路都失败 | 必须让 App 显示「已就绪」后再配对；已经错配的要在**电脑上删除该设备**后重配 |
| **两边同时建链** | 刚配对完手机立刻 `connect()`，Windows 同时也在反向连接，两条 L2CAP 请求互相顶掉 | 已改为：配对后等 2 秒让主机先动手；`connect()` 带去重 + 6 秒失败冷却 |
| **Boot 协议 `GET_REPORT` 回错** | Windows 用 `id=0` 索取输入报告，旧版回了 `HANDSHAKE_INVALID_REPORT_ID`，主机会判定设备损坏并主动断开 | 已改为：`id=0` 直接回当前键盘报告，未知 id 回零长报告而非错误码 |

现在未连接时诊断块会常显，里面有一段**事件日志**，能直接区分是哪一类：

```
14:02:11  BOND_BONDED Switch
14:02:13  connect(Switch) = true
14:02:13  CONNECTING Switch
14:02:19  DISCONNECTED Switch（未连上即失败）   ← L2CAP/HID 建链就没成功（SDP 缓存 / 加密问题）
```

- `未连上即失败` → 往 SDP 缓存、重新配对、加密方向查
- `曾连上后断开` → 链路已建立，问题在报告/协议层（看紧接着有没有 `GET_REPORT ...` 行）

## 已知限制



- 只支持「一块触控板 + 一只键盘」，不做多点触控直通（Windows 的 HID 触摸要 digitizer 集合，另说）。
- 不支持横向滚动（内置鼠标描述符没有 AC Pan），需要时可映射成 Shift+滚轮。
- 不做手柄/震动模拟：那属于表里的「手柄/震动」驱动项，和 HID 键鼠是两条路。
- 无 IME 服务，屏幕键盘只在 App 内可用（这是刻意的：按键要发往电脑，不是往手机输入框里打）。
